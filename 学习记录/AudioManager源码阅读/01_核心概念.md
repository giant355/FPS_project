# AudioManager 源码阅读 - 第 1 课：先看架构，再读代码

## 学习目标

本节结束后，你应能说明这个 `AudioManager` 的四项职责，解释它在 `Awake()` 中建立的三类数据，以及为什么要使用对象池。

## 内容讲解

这份代码不是“播放一段声音”的小脚本，而是一个长期存在的**音频调度中心**。可以把它想成游戏里的音效前台：

1. **混音器控制**：按轨道名（如 Music、SFX）读写音量，并能淡入淡出。
2. **对象池**：预先创建有限个带 `AudioSource` 的 GameObject，播放时反复使用，避免临时 `new GameObject` / `Destroy`。
3. **播放管理**：为每次播放分配唯一 ID，允许延时自动归还，也为“按 ID 停止”预留基础。
4. **优先级裁剪**：池满时，理论上用“距离听众更远、优先级更低”的声音让位给更重要的声音。

`Awake()` 是它的装配阶段：

```csharp
DontDestroyOnLoad(gameObject);
AudioMixerGroup[] groups = _mixer.FindMatchingGroups(string.Empty);
for (int i = 0; i < _maxSounds; i++) { ... }
```

- `DontDestroyOnLoad`：切换场景时不销毁管理器；因此 `_instance`、对象池、混音状态能持续存在。
- `FindMatchingGroups(string.Empty)`：空字符串匹配混音器中的全部组。随后代码用组名作为字典键，构造 `_tracks`。
- 循环创建 `_maxSounds` 个隐藏的 GameObject；每个都有一个 `AudioSource`，这就是对象池的固定容量。

三个核心集合分别回答三个问题：

| 字段 | 类型 | 问题 | 例子 |
| --- | --- | --- | --- |
| `_tracks` | `Dictionary<string, TrackInfo>` | “Music 对应哪个 Mixer Group？” | `"Music" -> TrackInfo` |
| `_pool` | `List<AudioPoolItem>` | “有哪些可复用 AudioSource？” | 固定 10 个池项 |
| `_activePool` | `Dictionary<ulong, AudioPoolItem>` | “ID 为 42 的声音在哪？” | `42 -> 正在播放的池项` |

注意：`AudioPoolItem.Playing == false` 表示该池项可拿来配置新声音；不是 Unity 的 `AudioSource.isPlaying`。这是管理器自己维护的状态，方便在池满时做决策。

## 小结

- 这是“混音控制 + 音效池 + 调度策略”的组合，不只是一个播放器。
- `Awake()` 一次性获取 Mixer 轨道，并预建固定数量的 AudioSource。
- `_tracks` 查轨道，`_pool` 管资源，`_activePool` 用播放 ID 找资源。
- 对象池的本质是用固定上限换取更稳定的运行时开销。
